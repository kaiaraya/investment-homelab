# InvestmentHomelab — Hermes rules (single source of project context)

Loaded automatically for any session whose cwd is inside this repo. `AGENTS.md` is only a pointer
to this file. Details that are not needed on every call live in `docs/agent/kanban_operating_model.md`.

## Platform (2026-10-26 migration)
- Everything runs in **Hermes**. The 4-agent hybrid loop (Argon / Flash 3.8 / Jules / Cline) is **retired**.
  Do not route work to Jules, Cline, or the Antigravity IDE; `scripts/jules_bridge.py` is in `scripts/legacy/`.
- The board is **`hermes kanban --board investment-homelab`** (durable SQLite, one card = one job).
  `docs/board/loop_board.md` is a **snapshot**, never the truth. `kanban_board.csv` is archived.
- The kanban dispatcher runs inside the Hermes gateway (`hermes-gateway` systemd user service).
  Gateway down ⇒ `ready` cards never spawn.

Card titles carry the tier so the list reads at a glance: `🟢 T0 ·` / `🟡 T1 ·` / `🔴 T2 ·` / `🔍 0a ·` /
`☁️ Colab ·`. The prefix is a human signal only — status is the machine gate.

## Tiers
- 🟢 **T0** — code/docs/unit test, touches no order, no OTP, no account switch. Dispatch freely.
- 🟡 **T1** — logic that still does not touch money/OTP but needs a careful review (validators, parsers,
  guardrails). Same lane, pin `gemini-3.1-pro`.
- 🔴 **T2** — order submit/amend/cancel · OTP · account switch · SBL live · live login/browser · merge `main`.
  Create it `blocked` and keep it that way until the human is physically watching. See "Live-money gate".

## Live-money gate (🔴T2)
A T2 card may run non-interactively **only** when all three hold:
1. `DRY_RUN_MODE=false` for that one run (never flip it yourself to make a test pass),
2. the broker browser is headed (`QUICKTRADE_HEADLESS=false`),
3. the human is at the screen and said "go" in chat for that specific card.
Otherwise leave the card `blocked`. Every T2 card carries a `## Witness Session` block (date, who, exact
side/symbol/vol/price, the go-ahead) before dispatch. Never close the browser mid-run; never weaken the
Anti-DW symbol assertion to make a flow pass.

## Probe gate (0a)
A card that touches broker DOM/XHR carries `Probe: PROBE_NEEDED` until a **read-only, headed** probe has
filled `## DOM / API Contract` with real selectors / XHR shapes (`Probe: PROBE_DONE`). A card whose probe is
not done is not ready — `scripts/preflight_card.py` refuses it. Probes never click Submit/Change/OTP.

## New ideas
Any idea, bug, or refactor found outside the running card's scope becomes a **new triage card**
(`hermes kanban --board investment-homelab create "<title>" --triage --assignee default`) — the specifier
fills the body and promotes it. Never widen the running card's scope, and never edit code inside a witness
card (open a side-quest card instead).

## Verify (mandatory per card)
- `.venv/bin/python scripts/verify_changes.py <changed files>` → exit 0 PASS · 1 FAIL · 2 BLOCKED/UNMAPPED.
- `--full` once at card close; never run two pytest at once (SQLite single writer).
- UNMAPPED → add the mapping to `MODULE_TEST_MAP`; do not guess tests.
- `scripts/preflight_card.py` before dispatch: secrets in the git index, `Probe: PROBE_NEEDED`, missing
  `## Witness Session` on T2.

## Trading safety (unchanged, non-negotiable)
- No tool call that places / amends / cancels an order unless the user asked for it in this task.
- No change to order / tick-size / price-volume validation logic outside the card's scope.
- Anti-Mock: never fabricate accounts, balances, order numbers or an empty book as success — report the
  real failure (`ORDER_UNVERIFIED`, `CANCEL_UNVERIFIED`, `NO_QUOTE`, …).
- Broker isolation: `kss` (TradeMan/QuickTrade/Streaming) and `lib` (Liberator WebTrade) selectors never mix.
- Never print credentials, PINs, tokens, or real balances (≥4 digits) into logs, dumps, chat, or reports.
- Zero-OTP: never trigger a broker SMS OTP unless `otp_relay_readiness.check().ready` is true; background
  jobs must never start a login/2FA.
- Never overwrite saved sessions in probes/tests (`data/session_state.json`, `data/liberator_session.json`).

## Compute offload (Colab)
Heavy GPU/CPU work (model 19, Monte Carlo, EOD ingest, parity runs) goes to the **Colab lane** through the
`colab` CLI (`colab new|install|exec|drivemount|download|log`), never into a worker card on this machine.
Artifacts return via Drive; the Colab lane never commits to the repo.

## Token discipline
- Read ranges, not whole files: `grep -n <symbol>` then ±60 lines. Never read a whole large file.
- `grep` the CODEMAP instead of reading it: `grep -n <symbol> docs/agent/CODEMAP.md`.
- Trim long output: `pytest -q --tb=line`, `| tail -40`.
- No images/base64 into a model — read DOM text. Vision needs `GEMINI_API_KEY` (see docs/agent/kanban_operating_model.md §Vision).
- Context > 60K tokens → compact and continue in a new session.

## Response style
Thai to the user, concise. Agent-facing reports (Worker / Review / Planner) in English bullets. Show the
diff and the evidence, not a replay of the process.
